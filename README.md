# Design Inspector

Бесплатный локальный Figma-плагин для просмотра свойств одного выбранного элемента и копирования CSS. Работает в редакторе Design, не требует Dev Mode, авторизации, сервера или платных API. Данные макета не покидают Figma; manifest запрещает внешние сетевые запросы.

## Установка и сборка

Нужны Node.js 22 LTS (22.12+) или 24 LTS и npm. Проверено на Node.js 24.14.0.

```sh
npm ci
npm run typecheck
npm test
npm run build
```

Сборка создаёт `dist/code.js` и автономный `dist/ui.html` со встроенными JS/CSS. Исходники интерфейса — HTML, CSS и TypeScript, компилируемый в обычный JavaScript; фреймворков нет.

## Запуск в Figma

1. Откройте файл дизайна в настольном приложении Figma.
2. В меню Plugins → Development → Import plugin from manifest выберите корневой `manifest.json` этого проекта после сборки.
3. Запустите Plugins → Development → Design Inspector.
4. Выберите один Frame, Rectangle или Text. Проверьте свойства и нажмите **Copy CSS**. Выделение другого элемента автоматически обновит панель; изменения свойств отслеживаются на текущей странице. **Refresh selection** позволяет перечитать данные вручную.
5. После изменения исходников выполните `npm run build` и перезапустите плагин.

В **Properties** можно скопировать отдельную CSS-декларацию, например `width: 1920px;`: кнопка справа от значения появляется при наведении или переходе клавишей Tab. На устройствах без hover кнопки видны постоянно. Успешное копирование кратко подтверждается в строке; ошибки буфера обмена показываются рядом с Properties. Для значений, которые генератор не может представить в CSS, кнопка не создаётся. **Copy CSS** копирует весь блок как прежде.

Для текстового слоя рядом с названием появляется **Copy Text**: копируется оригинальный `TextNode.characters`, включая пустой текст, переносы, пробелы и Unicode. Содержимое передаётся как строка по типизированному сообщению, без вставки в HTML. После копирования появляется подтверждение; при отказе Clipboard API используется резервное копирование, при неудаче показывается ошибка. **Copy CSS** продолжает копировать только CSS.

Название слоя занимает одну строку с многоточием; полное имя доступно при наведении в tooltip. Кнопка Copy Text не сокращает и не преобразует копируемый текст.

Properties и Spacing располагаются в две колонки при ширине окна от 700 px, ниже — друг под другом. CSS расположен под ними на всю ширину. Каждая из трёх секций независимо сворачивается по нажатию на заголовок; Enter и Space работают при фокусе на заголовке. Состояния раскрытия сохраняются через `figma.clientStorage` отдельно от размера окна и восстанавливаются при следующем запуске. При ошибке storage используются раскрытые секции. Длинные технические пояснения и причины пропуска CSS доступны во вложенных информационных блоках.

Потяните ручку в правом нижнем углу, чтобы изменить размер окна. Минимум — **320×300 px**, верхняя граница — **900×1200 px**, исходный размер — **380×640 px**. Если доступны `screen.availWidth/availHeight`, верхняя граница дополнительно уменьшается до размера экрана с запасом 32 px по ширине и 96 px по высоте для рамки и интерфейса хоста. На экране меньше минимального размера сохраняется минимум приложения. Ручка также доступна через Tab: стрелки меняют размер на 10 px, Shift + стрелки — на 50 px. Последние размеры сохраняются локально через `figma.clientStorage` и восстанавливаются при следующем запуске с повторной проверкой ограничений. Запись выполняется с debounce и по завершении resize. При недоступности storage инспектор продолжает работать с исходным размером. Длинные строки CSS прокручиваются внутри блока.

Основная область прокручивается отдельно от закреплённого footer: ручка не накрывает полосу прокрутки, нижние свойства доступны прокруткой. Перетаскивание использует `clientX/clientY`, а не только `screenX/screenY`: при постоянном или недоступном `screenY` прежний обработчик не видел вертикального движения. На завершении сохраняется последнее движение, без повторного расчёта по потенциально нулевым координатам terminal-события. Старый минимум высоты 400 px также мешал уменьшению ниже этой отметки.

Screen API сообщает рабочую область монитора, а не точный размер/позицию окна редактора Figma. Поэтому ограничения экрана — best effort; ограничение самого хоста или автоматическое перемещение окна не проверены в реальной Figma. Документированный минимум `figma.ui.resize` — 70×0; более строгие минимумы здесь заданы приложением. Если API выбрасывает ошибку resize, она показывается в footer, а неудачные размеры не сохраняются.

## Spacing Inspector

Секция **SPACING** показывает Top, Right, Bottom и Left вокруг условного элемента, X/Y — под схемой. Схема не обязана быть пропорциональной. Width/Height представлены только в Properties, без дублирования в Spacing. Кнопка у каждого значения копирует число с единицей, например `24px` или `1.5rem`. Переключатель px/rem и редактируемая база rem (по умолчанию 10 px) влияют только на показ и копирование. Поле базы отображается только в режиме rem; введённое значение сохраняется при переключении единиц. Данные Figma и CSS-блок не меняются. Значения округляются до 6 десятичных знаков; при некорректной базе rem копирование rem недоступно.

Измеряется **layout-прямоугольник**, а не нарисованный контур фигуры. Преобразование `inverse(parent.absoluteTransform) × node.absoluteTransform` переводит все четыре угла в систему координат родителя. Их охватывающий прямоугольник определяет X/Y (левый верхний угол), Width/Height (проекции на оси родителя) и знаковые зазоры до его границ. При повороте или skew эти внутренние проекции могут отличаться от исходных размеров в Properties; в компактной схеме они не выводятся повторно. Отрицательные зазоры означают выход за границы. Это геометрические расстояния, а не CSS margin или padding; CSS из них не генерируется.

Вложенность, Auto Layout, повороты родителя, отражения и skew учитываются через матрицы. Для Group используются её текущие производные границы: перемещение детей может изменить и размеры группы. `relativeTransform` здесь не используется, поскольку Figma определяет его с пропуском Group и Boolean Operation. Родитель Page не имеет конечного прямоугольника, а произвольный контур не задаёт прямоугольный контейнер: вместо измерений отображается пояснение. Вырожденные, численно нестабильные или недоступные матрицы также дают предупреждение. Strokes, тени, прочие эффекты и clipping не входят в измерения.

Ручная проверка в Figma после сборки и перезапуска:

1. Создайте Frame 300×200 и прямоугольник 80×50 в нём с X=20, Y=30. Ожидаются Top=30, Right=200, Bottom=120, Left=20, Width=80, Height=50.
2. Вложите Frame в другой Frame, затем поверните внешний контейнер. Локальные расстояния прямоугольника должны остаться прежними. Повторите с двумя элементами внутри Group; проверьте измерения относительно границ самой Group.
3. Включите Auto Layout и измените padding/gap/выравнивание. SPACING должен обновляться по фактической геометрии, не подменяя её CSS padding/margin.
4. Переместите прямоугольник в X=-10, Y=-5: Left/X=-10, Top/Y=-5. При X=250, Y=180 ожидаются Right=-30 и Bottom=-30.
5. Поверните прямоугольник на 45° или 90°. Проверьте охватывающий прямоугольник по осям родителя и пояснение о проекции. При 90° зазоры должны учитывать поменявшиеся местами проекции ширины/высоты, а Properties продолжает показывать исходные размеры слоя. Проверьте отражение элемента.
6. Для расстояния 24 px выберите rem: при базе 16 ожидается `1.5rem`, при базе 12 — `2rem`. Очистите базу, введите 0 или отрицательное число: должно появиться сообщение, копирование rem недоступно.
7. Проверьте кнопки всех шести значений, подтверждение копирования, выбор элемента без конечного родителя (Page), несколько выделенных элементов и отсутствие выделения.
8. Уменьшите окно до 320×300: таблица не должна выходить за ширину, нижний CSS доступен через прокрутку main, ручка остаётся вне полосы прокрутки. Проверьте Properties, Copy CSS, копирование отдельных деклараций и resize с повторным запуском плагина.
9. Выберите TEXT с несколькими строками, пробелами и emoji, нажмите Copy Text и вставьте в текстовый редактор. Повторите с пустым TEXT; для Frame кнопка должна исчезнуть. Проверьте, что длинное имя слоя ограничено одной строкой, tooltip содержит полное имя, а в буфер попадает содержимое текста, а не имя.
10. Перетаскивайте ручку строго по вертикали и по горизонтали, при длинном содержимом и внизу прокрутки. Отпустите указатель за пределами окна, повторите после потери фокуса. Перезапустите плагин и проверьте восстановление размеров. Фактическое поведение захвата и ограничений хоста требует ручной проверки в Figma.
11. Изменяйте ширину окна между 699 и 700 px: Properties/Spacing должны переключаться из одной колонки в две, CSS оставаться на всю ширину. Проверьте также 320×300 и максимально доступное окно.
12. Сверните разные комбинации секций, смените выделение и перезапустите плагин: состояния должны сохраниться. Пройдите Tab по заголовкам, откройте их Enter/Space; проверьте видимый focus, кнопки копирования и чтение подписей схемы скринридером. В режимах px/rem проверьте скрытие/появление базы и сохранение её значения. Контраст следует проверить в фактических светлой и тёмной темах Figma.

Для публикации получите собственный ID через Figma Create new plugin и добавьте его в manifest. Описание полей: [официальная документация Figma](https://developers.figma.com/docs/plugins/manifest/).

## Архитектура

```text
manifest.json              — точки входа, запрет сети
src/shared/contracts.ts    — сериализуемый контракт модулей
src/adapter/normalize.ts   — Figma API → нормализованные данные
src/adapter/spacing.ts     — получение геометрии родителя и элемента
src/geometry/spacing.ts    — чистая геометрия в координатах родителя
src/spacing/units.ts       — форматирование px/rem
src/css/generate.ts        — чистая генерация CSS без Figma API
src/main.ts                — события Figma и обмен сообщениями
src/ui/                    — HTML, CSS, vanilla DOM
scripts/build.mjs          — esbuild и встраивание UI
tests/                     — unit-тесты CSS, адаптеров, геометрии, единиц и UI
AGENTS.md                  — правила разработки и владение модулями
```

Контракт различает loading, empty, multiple, error и ready. Неопределимые значения отсутствуют в данных, причины показываются в предупреждениях. Код и имена слоёв выводятся как текст, не как HTML.

`generateDeclarations` формирует проверенные CSS-декларации. `generateCSS` собирает из них общий блок, а UI использует тот же генератор для кнопок отдельных свойств; преобразования значений в CSS в интерфейсе не дублируются.

## Ограничения MVP

- Только один элемент. Нет экспорта дерева, ассетов, HTML или адаптивной вёрстки.
- Размеры фиксируют текущее состояние в px; Hug/Fill, constraints и связи с родителем не восстанавливаются. `box-sizing: border-box` сохраняет внешние размеры при padding и внутренних границах.
- Поддерживается обычный горизонтальный/вертикальный Auto Layout. Wrap, grid, отрицательный gap и автоматический gap при space-between не экспортируются.
- Только одна видимая solid-заливка. Градиенты, изображения, несколько заливок и смешанные значения пропускаются.
- CSS border создаётся только для равномерного сплошного внутреннего stroke прямоугольных элементов; остальные strokes пропускаются.
- При совместном использовании Auto Layout, padding и stroke возможны отличия размещения содержимого: Figma может исключать stroke из расчёта layout, CSS border занимает место.
- Текст экспортируется только по достоверным общим значениям. AUTO line-height пропускается; вес не угадывается по имени стиля. Шрифты не устанавливаются и не встраиваются.
- Тени, blur, эффекты смешивания, трансформации, геометрия фигур, сглаживание углов и rich text не восстанавливаются. CSS — основа для разработчика, а не точная копия макета.
- Если буфер обмена недоступен в окружении Figma, панель предлагает выделить CSS и скопировать вручную.

Тесты используют нормализованные данные и mock-узлы Figma. Ручной запуск в Figma требуется отдельно: автоматические проверки не подтверждают работу реального хоста и clipboard.

Если панель не получает ответ от Figma за 8 секунд, она показывает ошибку связи. Нажмите кнопку обновления вверху панели. После обновления сборки закройте и снова запустите плагин, чтобы Figma загрузила новый интерфейс.

## v0.5 — Project Styles / CSS Import

В секции **Project Styles** выберите один или несколько `.css` файлов, включая собранный `main.css`. Панель показывает файлы, дату импорта, количество классов, переменных и правил. Повторный выбор файла с тем же именем заменяет его; отдельный file input у строки позволяет заменить файл с другим именем. Remove удаляет файл из анализа. **Refresh imported files** повторно читает сохранённые браузером File snapshots: чтобы получить новую версию с диска, выберите файл заново. Исходные файлы не изменяются.

Для WSL в файловом диалоге Windows откройте `\\wsl.localhost\<Distro>\home\<user>\<project>\...\main.css` (либо `\\wsl$\<Distro>\...`). Укажите своё имя дистрибутива и путь к собранному CSS. Дополнительное приложение и Node.js в среде плагина не нужны.

PostCSS разбирает CSS в данные; selector-parser разбирает селекторы, value-parser и color-string нормализуют значения. Сохраняются исходные значения, порядок, !important, источник, контекст media/вложенности и специфичность. Импортированный CSS никогда не вставляется в DOM, URL и @import не загружаются. Анализ работает в Web Worker; если хост запрещает Blob Workers, типизированный транспорт переносит обработку в sandbox основного потока плагина. Fallback не выполняет синхронный парсинг в UI, но обработка больших файлов может задержать события sandbox.

Ограничения: 8 файлов, 2 MiB на файл, 4 MiB суммарно, 12000 правил и 60000 деклараций суммарно. Дополнительно ограничены глубина, селекторы, развёрнутые компоненты деклараций и работа разрешения переменных. Ошибочный импорт сохраняет предыдущую версию этого файла. Несколько файлов импортируются последовательно; успешно загруженные файлы сохраняются при ошибке следующего.

Сохраняется один активный профиль: название, база rem (по умолчанию 10 px), имена файлов и компактные метаданные. Полный CSS и индекс остаются в памяти сеанса и не записываются в clientStorage. После перезапуска требуется повторный импорт: сохранённые строки служат напоминанием. Это ограничивает объём хранения несколькими KiB и не предполагает неограниченную ёмкость clientStorage. Индекс пересобирается при изменении файлов/базы rem и переиспользуется при изменении выделения.

## v0.6 — Style Matching

Поиск использует существующий CSS Generator для нормализованного элемента: размеры, цвета, границы, радиусы, типографику, padding, gap, flex и opacity. Эквивалентные поддержанные цвета, normal/400 и rem/px при указанной базе сравниваются одинаково. Относительные line-height (число, %, em) и letter-spacing в em сравниваются через собственный известный font-size каждой стороны. Прочие em, %, calc(), неизвестные значения и контекстные переменные не считаются достоверно равными. Shorthand разворачивается только при поддержанном синтаксисе; неизвестные эффекты остаются несравнимыми даже после последующего longhand.

Результат раскрывается в совпадения, различия, отсутствующие и несравнимые свойства, ограничения и покрытие каждым классом. **Copy class** копирует HTML class tokens только однозначных простых классов (в том числе с условными вариантами, без гарантии DOM-применимости); **Copy override** доступен после явного выбора кандидата при достоверных значениях и формирует только подтверждённо отличающиеся декларации. Missing/incomparable не добавляются. Override следует разместить после импортированных стилей.

Score = округлённое `100 × сумма весов совпавших компонентов / сумма весов всех сравниваемых компонентов`. Вес свойств font-*, line-height и letter-spacing — 2, остальных свойств модели инспектора — 1. box-sizing, opacity:1 и декларации вне модели инспектора имеют вес 0. Последние остаются в несравнимых и блокируют уверенное совпадение и override. Если совпало меньше двух смысловых групп, score ограничен 25. Компоненты padding, border, radius и gap считаются одной группой каждый. High требует безопасного кандидата, минимум двух групп, score ≥85 и отсутствия различий/несравнимых значений; medium требует безопасного кандидата, минимум двух групп, score ≥50 и отсутствия несравнимых. Остальные результаты имеют low. При равном score используется сумма весов совпадений, число классов, затем селектор. Score описывает покрытие импортированных деклараций, а не вероятность правильной вёрстки. Лимит top-12 применяется после оценки каждого класса; поиск пар по-прежнему ограничен 40 попытками.

Порядок файлов/правил и !important учитываются для простых классов одинаковой специфичности. Сложные селекторы, псевдоклассы, media, вложенные правила и прочий контекст не моделируются как браузерная cascade: такие результаты условные или неподдерживаемые, без готового Copy Class/Override. Глобальные правила и незагруженный @import также консервативно ограничивают уверенность. Специфичность сохраняется для анализа, но произвольная DOM cascade не вычисляется. Наследование, defaults браузера и неимпортированные стили неизвестны.

Предлагаются только достоверные :root-переменные; имена со scoped/conditional определениями или @property исключаются. Незагруженный @import отключает разрешение переменных. Комбинации ограничены 40 парами из 12 лучших частичных простых кандидатов; пары показываются только если улучшают score. Вывод ограничен 12 результатами. Полный перебор и комбинации из трёх классов не реализованы.

## v0.6.1 — числовое сравнение и действия кандидата

Числовое сравнение отделено от показа. После корректного преобразования в px допуск составляет `0.0001px + 2e-7 × max(abs(a), abs(b))` для учёта ошибок геометрии Float32. Для unitless opacity абсолютный допуск 1e-6; веса шрифта, строки, цвета и неизвестные единицы остаются точными. Разные единицы не сравниваются напрямую. rem использует Project rem base; относительные line-height и letter-spacing требуют собственного известного font-size кандидата. Font-size в em/% требует контекста родителя и остаётся несравнимым. В деталях и сгенерированном override числа округляются до четырёх десятичных знаков; внутренние данные не округляются для сравнения.

Внутри раскрытого кандидата доступны Copy class, Copy matched CSS и Use for override. Copy matched CSS сохраняет исходные значения (включая rem, var, shorthand, повторные декларации и !important), исходные селекторы и условные media/вложенные обёртки. Это фрагменты исходных правил, а не вычисленный стиль. Вывод ограничен 64 KiB на кандидата; при превышении кнопка недоступна с пояснением. CSS-файлы не изменяются.

По умолчанию селектор остаётся `.inspected-element`; первый найденный класс не выбирается автоматически. Use for override явно выбирает кандидат. Copy override появляется внутри выбранного кандидата только при безопасных подтверждённых различиях. При их отсутствии показывается No override needed. Для conditional-кандидата показывается причина недоступности override; low confidence сопровождается предупреждением об отсутствии DOM-подтверждения. Смена выделения, параметров или файлов сбрасывает выбор.

Ручная проверка v0.6.1 в Figma Desktop:

1. После сборки перезапустите плагин, импортируйте CSS и выберите TEXT. Сравните Figma line-height около 23.20000076px с CSS 23.2px: ожидается Matched и читаемое 23.2px.
2. Проверьте font-size:1.6rem при базе 10, line-height:1.45/145%/1.45em и letter-spacing:-.01em при font-size:16px. База 16 должна изменить результат для 1.6rem; неизвестный em/% font-size не должен давать точное совпадение.
3. Раскройте класс, проверьте Copy class без точки и комбинации через пробел. Для сложного селектора кнопка должна быть отключена. Copy matched CSS должен сохранить исходные значения и media wrappers.
4. До Use for override убедитесь, что селектор `.inspected-element`. Выберите класс с отличием: Copy override должен содержать только differing-свойства. При полном совпадении — No override needed. Для low/conditional проверьте предупреждения и ограничения.
5. Смените выделение: выбор селектора должен сброситься. Проверьте clipboard и прежние Properties, Spacing, Copy CSS, Resize при минимальном размере окна.
